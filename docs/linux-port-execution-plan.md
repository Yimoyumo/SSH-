# SSH 工具 Linux 版本移植执行计划

- 文档状态：待执行
- 编写日期：2026-11-11
- 首个目标平台：Ubuntu 24.04 LTS x86_64
- 首个交付形式：`.deb` 安装包及对应构建产物
- 预计工程量：4～7 人日，由一名熟悉 Go/Wails 的开发人员执行
- 核心约束：现有功能不变；允许替换平台专属依赖；不得降低凭证存储安全性

## 1. 背景与判断

当前项目采用 Wails v2、Go、React 和 xterm.js。SSH、SFTP、终端、多标签、配置及日志逻辑基本具备跨平台条件，主要障碍是 `app/vault.go` 直接调用 Windows DPAPI。

本次移植不更换桌面框架，不重写 SSH/SFTP 和前端。工作重点是：

1. 建立可重复的 Linux 构建环境。
2. 用 Linux Secret Service 替代 DPAPI。
3. 验证系统对话框、剪贴板、拖放和终端渲染。
4. 完成 Ubuntu 安装包及完整功能回归。
5. 确保 Windows 版本原有能力不因平台拆分而退化。

当前估算基于静态代码检查。执行前尚未在 Linux 上完成编译和运行验证，因此第一阶段必须先消除环境及构建不确定性。

## 2. 目标与边界

### 2.1 交付目标

- Linux 版现有功能与 Windows 版一致。
- 密码、私钥及私钥口令不以明文写入配置文件或日志。
- 支持 Ubuntu 24.04 LTS x86_64 的 GNOME 桌面，覆盖 X11 和 Wayland 会话。
- 提供可从干净系统安装、启动和使用的 `.deb` 包。
- Windows 版仍能构建，连接配置、终端和 SFTP 行为保持原样。
- 提供构建说明、回归结果和已知限制。

### 2.2 非目标

以下内容不纳入首版，避免扩大移植范围：

- 不同时承诺 Fedora、Arch、其他架构或所有桌面环境。
- 不替换为 Electron、Tauri 等其他桌面框架。
- 不新增同步、自动更新、插件、主题等功能。
- 不实现 Windows DPAPI 密文到 Linux 的迁移；Linux 首次使用时重新录入凭证。
- 不实现无 Secret Service 环境下的主密码加密兜底。
- 不改变当前主机密钥校验策略或其他与移植无关的安全行为。
- 不借移植进行大规模重构或建立新的自动化测试体系。

## 3. 技术决策

| 项目 | 决策 | 原因 |
| --- | --- | --- |
| 桌面壳 | 保留 Wails v2 | 已支持 Linux，可避免重写前后端桥接 |
| SSH/SFTP | 保留 `golang.org/x/crypto/ssh` 和 `github.com/pkg/sftp` | 与本地操作系统无关 |
| 前端 | 保留 React、TypeScript、xterm.js | 未发现 Windows 专属界面逻辑 |
| Windows 凭证 | 保留现有 DPAPI 实现 | 避免破坏 Windows 已存配置 |
| Linux 凭证 | 使用 Secret Service，优先采用 `github.com/zalando/go-keyring` | 对接 GNOME Keyring，避免自研密钥管理 |
| 配置与日志 | 保留 `os.UserConfigDir` | Linux 下自然落到 XDG 配置目录 |
| 终端渲染 | 保留 WebGL，并保留现有失败回退 | 降低 WebKitGTK 渲染兼容风险 |
| 安装包 | 首版只提供 `.deb` | 可声明 GTK/WebKit 等运行依赖 |
| 明文兜底 | 禁止 | Secret Service 不可用时必须明确报错 |

### 3.1 凭证存储设计

1. 将现有 Windows 实现放入带 `//go:build windows` 的文件，新增带 `//go:build linux` 的实现。
2. 保持上层 `Encrypt`/`Decrypt` 调用语义，避免改动 SSH 认证流程。
3. Linux 实现将真实凭证写入 Secret Service，配置 JSON 只保存不可直接用于认证的凭证引用。
4. 引用包含格式版本和随机标识，服务名统一为 `ssh-tool`，避免与其他应用冲突。
5. 更新连接时，在新配置成功落盘后再清理被替换的旧凭证；保存失败时回滚本次新建凭证。
6. 删除连接时同步清理关联凭证；清理失败必须记录并返回可诊断错误，不得静默忽略。
7. 编辑连接但未修改凭证时继续引用原凭证，不重复创建。
8. Secret Service 不可用、被锁定或访问被拒绝时，向用户显示明确错误，不写明文文件。
9. 日志只记录操作、连接标识和错误，不记录密码、私钥、私钥口令或 Secret Service 中的秘密值。

### 3.2 Linux 构建策略

- Go 版本服从 `go.mod`，Wails CLI 与项目 Wails v2.12.0 依赖保持一致。
- Ubuntu 24.04 使用 GTK3 和 WebKitGTK 开发包；若目标环境的 Wails 构建需要 WebKitGTK 4.1，使用对应的 `webkit2_41` 构建标签。
- 以 `wails doctor`、实际构建和干净虚拟机运行结果确定最终依赖清单，不凭开发机已安装的隐式依赖发布。
- 前端锁文件继续由 pnpm 管理，构建前执行类型检查和 Vite 构建。

## 4. 预计改动范围

以下代码路径均相对于 `ssh-tool/` 工程目录。

| 文件或区域 | 预期处理 |
| --- | --- |
| `app/vault.go` | 拆分 Windows 与 Linux 平台实现，保留清晰构建标签 |
| `app/app.go` | 在连接更新、删除流程中接入凭证清理及失败回滚 |
| `app/ssh.go` | 原则上不改，仅处理新凭证接口暴露出的必要适配 |

| `frontend/src` | 原则上不改；仅修复 Linux 实测发现的对话框、剪贴板、拖放或渲染问题 |
| `README.md` | 补充 Linux 构建、安装、运行依赖和已知限制 |
| `build` 或发布脚本 | 增加最小 `.deb` 打包配置，不引入新的发布体系 |
| 测试与验收记录 | 记录本计划中的回归矩阵结果及环境信息 |

## 5. 分阶段执行

### 阶段 0：基线与构建环境（0.5 人日）

任务：

1. 准备 Ubuntu 24.04 x86_64 干净虚拟机，分别确认 X11 和 Wayland 测试条件。
2. 安装 Go、Node.js、pnpm、Wails CLI、编译器、`pkg-config`、GTK3 和 WebKitGTK 开发依赖。
3. 执行 `wails doctor`，记录版本及缺失项。
4. 在 Windows 版按第 7 节矩阵跑一次基线，记录现有行为和已存在问题，避免把旧问题算成移植回归。
5. 确认一个可用于密码、私钥和加密私钥登录的 SSH/SFTP 测试服务器。

完成条件：

- 环境版本、测试服务器和 Windows 基线均有记录。
- 所有构建依赖来源明确，没有依赖开发机上的未记录状态。

### 阶段 1：平台拆分与构建准备（0.5～1 人日）

任务：

1. 执行前端依赖安装、TypeScript 检查和 Vite 构建。
2. 为现有 DPAPI 文件补充 Windows 构建约束，并建立 Linux 真实凭证实现的文件边界。
3. 确认剩余 Linux 编译阻塞仅限于尚未接入的凭证实现，不引入明文、空实现或其他临时桩。
4. 准备 Wails Linux 构建命令及 WebKitGTK 构建标签，在阶段 2 接入真实凭证后执行完整构建。
5. 确认 Windows 平台文件仍参与原构建路径。

完成条件：

- 前端构建成功。
- 平台文件边界清晰，没有临时凭证桩。
- Linux 构建命令和依赖已确定，可供阶段 2 重复执行。
- Windows 构建路径未被 Linux 构建标签破坏。

### 阶段 2：Linux 凭证存储（1～1.5 人日）

任务：

1. 引入并锁定 Secret Service 客户端依赖。
2. 按第 3.1 节实现 Linux 凭证写入、读取、更新、删除和错误处理。
3. 打通 Linux 后端及 Wails 应用完整构建，确认命令可从干净检出重复执行。
4. 验证新建、编辑保留、编辑替换和删除连接四种路径。
5. 检查配置 JSON、应用日志和错误信息，确认没有秘密值泄漏。
6. 验证应用重启后仍可读取凭证并建立连接。
7. 验证 Secret Service 不可用或拒绝访问时的用户提示。

完成条件：

- Linux 后端及 Wails 应用完整构建成功。
- 密码、私钥、私钥口令均可完成保存、读取和认证。
- 配置 JSON 不含明文凭证，凭证引用在重启后有效。
- 更新及删除不会无限遗留旧凭证，失败路径可诊断。
- 无明文兜底，Windows DPAPI 行为不变。

### 阶段 3：平台行为适配（0.5～1 人日）

任务：

1. 验证配置和日志位于预期 XDG 用户目录，普通用户权限可读写。
2. 验证打开文件、保存文件对话框的取消和确认路径。
3. 验证终端右键及快捷键复制粘贴，覆盖 X11 和 Wayland。
4. 验证文件选择上传和拖放上传；若 WebKitGTK 下拖放不能提供本地路径，必须修复拖放链路，可将文件选择上传作为回归对照，但不能以功能降级通过验收。
5. 验证终端字体、中文、窗口缩放、标签切换和 WebGL 回退。
6. 只修复实测问题，不对跨平台代码做预防性重写。

完成条件：

- 所有现存用户入口均有与 Windows 版一致的结果，包括文件选择和拖放上传。
- 应用启动、窗口和终端渲染无阻断性问题。

### 阶段 4：`.deb` 打包（0.5～1 人日）

任务：

1. 生成 release 构建，记录完整构建命令。
2. 编写最小 `.deb` 元数据，声明实际 GTK、WebKitGTK 和其他动态链接依赖。
3. 在干净 Ubuntu 虚拟机安装，确认依赖可解析、应用可启动。
4. 验证普通用户安装和运行，不要求 root 运行应用。
5. 生成安装包校验值，记录包版本、架构和构建环境。

完成条件：

- `.deb` 可在干净目标系统安装、启动和卸载。
- 运行时不存在未声明的动态库依赖。
- 安装包不携带开发机配置、日志或凭证。

### 阶段 5：全量回归与发布（1～1.5 人日）

任务：

1. 按第 7 节逐项执行 Linux 功能回归，覆盖 X11 和 Wayland 的关键路径。
2. 对 Windows 版执行构建和核心功能回归，重点检查凭证读取、连接保存及终端/SFTP。
3. 修复本次移植引入的问题后，重新执行受影响项及对应构建。
4. 更新 README 的 Linux 安装、构建、Secret Service 要求和已知限制。
5. 汇总交付物、验收结果和未覆盖平台。

完成条件：

- 第 8 节发布门槛全部满足。
- 没有阻断或高优先级移植回归。
- 未验证的平台和限制明确写出，不作笼统兼容承诺。

只有同时满足以下条件才宣布 Linux 首版完成：

- 所有构建命令执行成功，退出码为 0。

- 干净 Ubuntu 24.04 虚拟机可通过 `.deb` 完成安装和使用。
- Windows 核心回归通过。
- 不存在功能缺失、静默明文保存、启动崩溃或核心流程不可用。

## 9. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Secret Service 在精简桌面或锁定时不可用 | 无法保存或读取凭证 | 首版明确支持范围并返回错误；主密码兜底另行排期 |
| Ubuntu 24.04 WebKitGTK 版本与默认 Wails 构建不一致 | 构建或运行失败 | 阶段 0 用 `wails doctor` 和实际构建确认 4.1 及构建标签 |
| Wayland 剪贴板或文件拖放行为不同 | 用户入口受限 | 同时测 X11/Wayland；快捷键、文件选择和拖放均须通过，不能以降级验收 |
| WebKitGTK 的 WebGL 表现不同 | 终端显示或性能异常 | 验证现有回退，必要时在 Linux 默认使用稳定渲染路径 |
| 凭证更新和删除清理不完整 | 遗留无用秘密或失去可用凭证 | 先保存新状态再清理旧值，失败回滚并记录可诊断错误 |
| 开发机隐藏依赖导致安装包不可用 | 干净系统无法启动 | 使用干净虚拟机验收，并检查动态链接依赖 |
| 当前缺少自动化回归 | 问题发现较晚 | 使用固定测试服务器和本计划矩阵进行真实功能验收 |
